## A01｜这条命令会运行哪个文件？

A01 解决“先运行到正确的文件”。**PowerShell 找到并启动 Python → Python 取得脚本路径和工作目录 → 打开文件执行。** 文件找对以后，才进入 A02 的程序内部值流。

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| `.\hello.py` 指哪份文件？ | `.` 表示当前目录；相对路径与当前工作目录合起来，才能确定目标。编辑器打开谁，不会替命令决定目标。 | **直接认得 `.`；能按当前位置展开目标。** 文件夹名和盘符不背。 |
| 查位置、换位置、核对文件，分别用什么？ | `Get-Location` 查看当前目录；`Set-Location` 改变当前目录；`Resolve-Path` 核对已有目标的完整位置。 | 逐渐认熟三个动作；完整选项可查。这不是每次运行前必须执行的一套流程。 |
| 不想依赖当前位置，怎样指定脚本？ | `python 'D:\FDE-Lab\A01\前台\hello.py'` 用绝对路径指定目标；`python .\前台\hello.py` 利用当前位置与文件的关系。 | 熟悉 `python` 后接脚本路径；绝对路径是否有效仍取决于文件实际位置。 |
| 运行了前台文件，当前位置也变了吗？ | **运行某处的脚本，不会自动把 PowerShell 切换到那里。** 打开的脚本与继承的工作目录可以不同。 | 分清“文件在哪里”和“从哪里运行”，不用默写术语定义。 |
| 报错时先改哪里？ | `can't open file` 表示 Python 启动了，但没能打开目标，脚本正文尚未执行；找不到 `python` 则更早，启动入口就有问题。 | 先读错误中的目标与失败位置，再选排查层次。 |

例如当前目录是 `D:\FDE-Lab\A01`：

```text
.\前台\hello.py → D:\FDE-Lab\A01\前台\hello.py
.\hello.py      → D:\FDE-Lab\A01\hello.py
```

运行第一份文件，不会让第二条路径自动继承“前台”。这里是地址展开示意，不要求创建这些文件。`Resolve-Path` 是运行前核对证据的工具，不是 Python 启动时必须经过的一步。

保存脚本时，认清**纯文本、真正以 `.py` 结尾、UTF-8 编码**。路径有空格时，用引号把整个参数括住；`-LiteralPath` 表示按给定路径处理，不把其中的字符当通配符。具体命令可查，已有文件不要随意覆盖。

回看：路径定位见「这条路径从哪里开始找？」「不改变当前位置，也能指定前台文件吗？」；错误见「文件没打开时，错误信息会告诉什么？」；保存与启动入口见「在电脑上试一遍」。

## A02｜输入怎样变成可继续使用的结果？

文件开始执行后，要追的是**拿到什么值 → 哪个操作产生新值 → 谁接住 → 下一步怎样使用**。本章把输入、计算和显示分开，后面才能判断条件和检查函数。

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 输入了数字，为什么不能直接按人数计算？ | `input(...)` 交回字符串；`int(raw)` 尝试得到整数。`"12" * 2` 得到 `"1212"`，整数 `12 * 2` 才得到 `24`。 | **认熟输入与转换的作用，先看类型再解释结果。** 转换成功不等于符合业务范围。 |
| `people = int(raw)` 怎样执行？ | 先求右边，再让左边名字对应结果。转换不会自动把 `raw` 改成整数；右边失败，这次赋值没完成。 | 赋值方向和先后要能追踪；变量名按任务改变。 |
| 清理文字以后，为什么原值没变？ | `cleaned = raw.strip()` 接住去掉两端空白后的新字符串；不用返回结果，`raw` 仍对应原字符串。 | 逐渐用熟“取得结果再使用”；不能见到方法调用就假定原值改变了。 |
| 数字怎样放进说明，又继续计算？ | `f"需准备 {total} 瓶水"` 产生文字，不改变数值 `total`；`float(...)` 用于把合适的文字转换为浮点数。 | 认熟 f-string 的 `f` 与 `{...}`；格式参数按需查。 |
| 自己的函数怎样交接？ | `def` 建立函数，调用才运行函数体。参数接值，`return` 结束本次调用并把结果交回调用处；局部名字不自动成为外部变量。 | 沿传入值、计算、返回、接收一路追踪；不默写术语定义。 |
| 已打印结果，外面为什么拿不到？ | **`print` 显示给人，`return` 交回代码。** 函数走到末尾而未明确返回结果，会交回 `None`，不是数值 `0`。 | 这是需要直接分清的区别；屏幕输出和调用结果分别看。 |

同一份输入的值流：

```text
"12" → int 得到 12 → 乘 2 得到 24
     → 计算函数 return 24 → 调用处接住，再计算或显示
```

`round(value, 2)` 得到舍入后的数值，`f"{value:.2f}"` 得到两位小数的文字；二者都不自动改掉 `value`。浮点数可能近似保存，显示位数不等于内部精度。

回看：转换见「输入的是 12，为什么乘 2 得到 1212？」；清理见「输入两端有空格时，清理结果去了哪里？」；小数见「计算结果有小数，和显示几位小数是一回事吗？」；交接见「计算能不能交给一个自己定义的函数？」「函数里已经打印了 24，为什么外面还拿不到它？」。

## A03｜程序为什么走这一条路？

A02 提供值；A03 把值交给条件，决定**检查谁、执行哪一段、何时返回**。结果不只取决于条件怎么写，还取决于实际检查顺序。

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 赋值、比较、分支分别做什么？ | `=` 赋值；`==` 判断相等，`!=` 判断不等。比较产生 `True` 或 `False`，`if` 再决定是否执行缩进块。 | **直接分清 `=` 与 `==`。** 条件不成立通常是跳过块，不是整个程序结束。 |
| 只选一个结果，还是分别检查几件事？ | `if/elif/else` 从上往下选中一段后，跳过同一链的其余分支；多个独立 `if` 则各自检查。 | 按任务选结构。独立判断后再次赋值，可能覆盖前面的结果。 |
| 同样条件，换顺序为什么出错？ | 先排除不合格年龄，后面才可只检查类别。`else` 承接前面未选中的情况，不自动保证输入合法。 | **能指出某值走到哪里，到此已排除了什么。** 示例年龄与票种不背。 |
| 全部成立，还是任一成立？ | 比较条件用 `and` 表示都满足，`or` 表示任一满足；`not` 反转真假。`12 <= age <= 70` 包含两端。 | 用熟连接方式与边界；左边已能决定结果时，右边可能不执行。 |
| 怎样从计算形成条件？ | `%` 取余；`ticket_no % 2 == 0` 先算除以 2 的余数，再判断是否为零，用于本章票号的奇偶分流。 | 认熟“算值 → 比较 → 分支”。`%` 自己不会选择路线。 |
| 不合格时能直接结束判断吗？ | 函数里的 `return` 结束整个当前调用；`elif` 只控制这条分支链。赋值或打印不会自动结束函数。 | 按作用范围区分，不把提前返回与分支链看成同一个机制。 |

例如年龄不合格且名额为零：若函数先返回年龄拒绝，名额条件单独看虽也成立，**实际却没被检查**。不能把所有真条件都列成发生过的结果；返回“接受”也不代表已经扣减名额或保存记录。

把固定文字选项映射成名称，可用分支链，也可用本章 `match/case`。`case _` 接住前面未匹配的情况；不把它替代所有范围判断。完整写法和版本条件查「只是把票种换成名称，需要整套报名判断吗？」。

这里的 `and/or` 连接比较结果；不要外推成它们无论接什么值都只返回布尔值。

回看：分支见「把 elif 换成另一个 if，结果为什么变了？」；组合见「“任意一个不合格”和“全部都符合”怎样表达？」；优先级见「多条不合格规则，能不能发现一条就返回？」。

## A04｜下一次从哪里来，又在哪里停？

A03 处理一条记录的去向；A04 处理多轮工作。**循环负责继续，列表和字典组织内容，跨轮变量保留过程中的事实。** 它们目前在内存中，不会在程序结束时自动存入文件。

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 下一轮怎样发生？ | `while` 回到条件重查，但不会替代码更新条件依赖的值；`for item in items` 每轮取得下一项，没有下一项便结束。 | 按来源选择：检查是否还要继续，或依次处理来源中的项目。`for` 不只遍历列表。 |
| 怎样保留录入，不只剩最后一项？ | `records = []` 建列表；`records.append(record)` 加到末尾。列表在收集前建立，不在每轮清空。 | 用熟添加。**`append` 改变列表，返回 `None`；别把返回值再赋给列表名字。** |
| 按位置取值，为什么容易越界？ | `names[0]` 取第一项，`len(names)` 是数量。`range(3)` 提供 `0、1、2`，不含 `3`；`range(len(names))` 提供位置，不是姓名。 | 认得从 `0` 开始、上限不包含；只需要项目本身时直接遍历。 |
| 按编号或字段查，用什么组织？ | 字典按键取值，如 `status_by_id["R102"]`；同键再次赋值替换旧值。`key in mapping` 判断键是否存在。 | 分清位置与键；直接读取不存在的键会产生 `KeyError`，不是自动忽略。 |
| 多人、每人多字段，怎样连接？ | 列表保存多条字典；`records[0]["status"]` 先取第一条，再取状态字段，是两次取值。 | 沿结构找值；容器不自动保证字段完整或内容有效。 |
| 怎样记住“前面曾出现候补”？ | 标记在循环前初始化为 `False`，见到候补改为 `True`；后续不应无故清回去。 | **状态放哪里、何时更新，要看它记一轮还是整个过程。** 不给每个循环强加标记。 |
| 提前停循环，与交回结果有什么不同？ | `break` 离开最内层当前循环，仍可执行循环后代码；`return` 离开整个当前函数，交回调用处。 | 能指出下一步去哪；空来源也可能一次都不进入循环。 |

嵌套时，外层每次走到内层，都会开始这次内层遍历；内层 `break` 不自动结束外层。座位例见「每行还有几个座位，内层循环会重新开始吗？」。

录入程序保存了工作人员填写的状态，不代表已校验状态。结束词 `end` 要先判断再添加，避免当成姓名；录入与报告可分两段，由列表交接。

回看：推进见「同一段代码，为什么会再执行一次？」；添加见「append 与字符串清理的结果为什么不同？」；取值见「需要第几位时，位置和人数有什么区别？」「知道报名编号，不知道它排第几位，怎样查状态？」；状态见「怎样在循环结束以后，仍记得出现过候补？」。

## A05｜出错以后，程序怎样继续？

程序已有输入、判断和循环；本章补上**某一步做不成以后，哪些代码不能继续，可靠结果又怎样交给后续工作**。

主线是：尝试转换 → 失败时改道，成功时使用结果 → 循环决定重试 → 函数返回后，调用者检查业务规则。

### 出错时，先找最早没完成的操作

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 还没执行就报错，还是运行中做不成？ | 普通脚本结构无法解析时出现 `SyntaxError`，程序体尚未开始；`int("cat")` 则是运行时转换失败。 | 分清失败阶段；缺引号不能靠尚未运行的 `try` 修好。 |
| 转换失败，左边得到什么？ | `people = int("cat")` 的右边没产生整数，**这次赋值没有完成**。不是得到 `0` 或 `None`；名字若原来有值，也不会自动清除。 | 理解“先算右边，再赋给左边”；不背整行错误信息。 |
| 失败以后从哪里继续？ | `try` 尝试操作；匹配的 `except ValueError:` 接住块内这种失败，跳过 `try` 剩余部分，处理后再往下走。 | 用熟精确捕获；不靠空 `except` 隐藏所有问题。 |
| 转换失败后，为什么又有 `NameError`？ | 本次运行从未建立的名字，不能直接拿来用。`try` 不是特殊作用域；问题是赋值没完成。 | **异常被处理，不代表成功结果已存在。** |
| 成功计算放哪里？ | `try/except` 的 `else:` 在 `try` 无异常、正常走完时进入；依赖转换结果的计算可放这里。 | 用熟成功与失败分路；这个 `except` 不捕获 `else` 内新发生的异常。 |

回看：「等号右边先产生结果，左边才接得到」「只圈住转换以后，成功代码不能随便放」「`else` 接住“尝试成功”的路线」。

### 重试和交接，分别由谁负责？

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 提示错误后，为什么没重新询问？ | `except` 不重跑输入。控制回到包含 `input()` 的循环，才有下一轮；`pass` 只是不做额外动作。 | **重试靠循环，不靠异常名称或 `pass`。** |
| 应离开循环，还是交回结果？ | `break` 离开当前循环；`return value` 结束当前函数，把值交回调用位置。 | 值得直接记住的范围区别；`return` 不是另一个 `break`。 |
| 转成整数，为什么仍不能接受？ | `int("-2")` 成功；人数须大于零，则由调用者的 `if` 拒绝。`get_int(prompt)` 只负责取得转换成功的整数。 | **转换成功 ≠ 业务有效。** 返回值再交给哪条规则，要看调用者。 |

例如 `people = get_int("预计到场人数：")`：提示文字传进去，函数取得整数后 `return`，左边才接到结果。`get_int`、`prompt` 是示例命名，不是固定语法。

回看：「为什么处理一次不会自动重新询问」「完整程序：转换规则和活动规则分开」。

Fuel、Taqueria 是可选迁移，不承担核心前提。需要时查「可选迁移一｜Fuel Gauge 还多了哪些关系」「可选迁移二｜Taqueria 怎样处理字典、未知菜名与输入结束」：拆包也可能产生 `ValueError`；`except (A, B)` 接其中任意一种；`continue` 跳过本轮剩余代码；未知字典键不会自动忽略，`EOFError` 则表示输入来源结束。这里的 A、B 代表异常类型，不是照抄的名称。

## A06｜别处的代码，怎样为当前程序工作？

A05 把工作分给函数；本章让函数不必都写在当前文件。**代码来源 → 导入建立名字 → 传参并调用 → 返回结果 → 当前程序继续使用。**

### 需要的能力，怎样带进来？

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 代码从哪里来？ | 标准库随 Python 提供；自写模块来自项目文件；第三方库通常先安装到实际使用的环境。 | 三种来源不等于三种调用原理。**导入模块不是与另一个独立运行的程序通信。** |
| 为什么有时带模块名，有时不带？ | `import random` 建立模块名，调用 `random.choice(...)`；`from random import choice` 建立函数名，调用 `choice(...)`。 | 用熟两种形式，能指出名字来源；不靠 `import *` 隐藏来源。 |
| 抽一项和算平均，用同一种工具吗？ | `random.choice(名单)` 返回一项，不删除它，也不保证每次不同；`statistics.mean(数字列表)` 算平均。空数据不能自动当作零。 | 记用途，函数名可查；先明确要得到什么结果。 |
| 自己的另一个文件怎样使用？ | `import ticket_tools` 不写 `.py`；`ticket_tools.format_sample("T-104")` 将编号交给该模块函数，接回文字。 | 与本文件函数一样追踪参数和返回；找不到模块先查名字、位置和环境。 |

回看：「换一种 import，调用名字为什么也变了？」「自己写的显示规则，也能放在另一个文件里吗？」。

### 输入、启动与导入，不是同一个动作

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 不改代码，怎样传入本次数据？ | `sys.argv` 是启动参数列表；本章脚本启动方式中，第 0 项是脚本，`sys.argv[1:]` 取得后面的参数，仍是字符串。 | 认熟 `[1:]` 的取值意思；不删除原列表，也不重新等待键盘输入。 |
| 没给参数时怎样结束？ | 本例用 `sys.exit("说明")` 表达命令应结束；`return` 只结束函数并交回结果。 | 记区别；`sys.exit` 不是无条件强制杀进程。退出状态在 A10 展开。 |
| 为什么只导入就有额外输出？ | 通常第一次导入会执行模块顶层代码；`def` 建立函数，函数体仍要等调用。 | **导入不是只登记文件名，也不是调用全部函数。** |
| 怎样只在直接运行时启动演示？ | `if __name__ == "__main__":` 控制缩进内的启动调用；导入时其他顶层代码仍会执行。 | 值得逐渐写熟；不是“别人使用时才运行”的条件。 |
| 第三方库能导入，任务就成功了吗？ | 安装让环境可找到库；导入加载名字；调用 `httpx.get(...)` 才实际发请求。服务不在线或返回错误内容是后面的事。 | 安装、导入、调用结果分别核对；环境命令与版本细节查用。 |

HTTPX 响应的 `status_code`、`text` 是这次回应的信息；读取属性不是再发请求。完整本地服务准备留作配方，不必背启动命令才能理解模块协作。

回看：「不改源代码，怎样换一批工单？」「为什么只导入一个文件，也可能出现额外输出？」「HTTPX 为什么还需要安装，而 random 不需要？」。

## A07｜怎样知道这次修改真的修好了？

有返回值不等于结果正确；修好一个案例不等于旧功能没被破坏。**从要求推出预期 → 比较实际值 → 定位最早差异 → 修改 → 重跑原检查。**

### 测试写什么，工具增加什么？

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 预期从哪里来？ | 九点半应为 `9 × 60 + 30 = 570`。预期来自换算要求，不是抄程序输出。 | **先有判断依据，再让工具比较。** |
| 怎样把要求写成检查？ | `assert actual == 570` 检查条件；为假时发出 `AssertionError`，不替程序修正数值。 | 用熟 `assert 实际结果 == 预期结果`；比较用 `==`，赋值用 `=`。 |
| pytest 是“激活 assert”吗？ | 不是。`assert` 属于 Python；pytest 找到测试、调用测试、汇总结果，并增强差异报告。 | **断言提出要求，pytest 组织执行。** 定义测试函数不等于已调用。 |
| 报告指向 assert，就该改测试吗？ | 那可能只是发现差异的位置。先核对预期，再沿调用追进业务函数，检查输入与计算。 | 不为变绿而把正确预期改成错误输出。 |

这个独立短例把两份工作放在一起展示：

```python
def to_minutes(hours, minutes):
    return hours * 60 + minutes

assert to_minutes(9, 30) == 570
```

函数产生实际值，断言核对它；`570` 来自要求，不是固定语法。若把函数误改为只返回 `hours * 60`，整点 `(9, 0)` 仍能通过，非整点 `(9, 30)` 才暴露遗漏。选择案例是为了让不同错误显现，不是随意多试几个数字。正式项目通常分别保存可复用业务函数与测试。

要实际重复这些检查时，再查运行入口 `python -m pytest test_time_slots.py -q`：让所选 Python 运行 pytest，文件名选目标，`-q` 减少报告细节。它要求当前环境已经安装 pytest、当前位置能找到测试文件；原章提供自己的 `.venv` 入口。命令逐渐用熟，不在值与预期还没分清时先背环境配方。

回看：「九点算对了，九点半就一定算对了吗？」「检查多起来，谁负责一个个调用？」「报告指向 assert，是测试文件写错了吗？」。

### 测试、业务校验和排错，各管哪一段？

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 能依赖 assert 拦截正式业务坏输入吗？ | 不应依赖它：优化运行可能移除断言。业务规则用普通 `if`；约定拒绝时，可用 `raise ValueError(...)` 发出异常。 | **测试检查要求，业务代码执行规则。** `raise` 发出异常，`except` 处理异常。 |
| 本来就该报错，怎样测试通过？ | `with pytest.raises(ValueError):` 检查块内调用是否发生预期异常；没发生或发生不匹配异常，都不符合预期。 | 认得用途；完整写法查「不合法的时间本来就该失败，怎样测试？」。 |
| 打印对了，返回值为什么不对？ | `print` 交给输出通道；`return` 交给调用者。只打印、没返回业务值时，调用结果可能是 `None`。 | 屏幕看见结果与调用者收到结果分别看。 |
| 怎样选案例，而不穷举全部输入？ | 选择能暴露不同遗漏的情况：整点、非整点、实际范围边界和约定拒绝路线。修复后也重跑原来正确的案例。 | 不背案例数字、不凑数量；通过只支持实际检查过的情况。 |
| 仍找不到原因，看什么？ | 最小失败调用、临时值输出或断点帮助定位；回溯是异常传出的调用路径，不是全部执行历史。日志留下以后可查的线索。 | 已定位就修复复查；需要暂停看值时查「值太多时，怎样暂停下来逐步看？」。日志不记录秘密。 |

重点不是报告格式，而是**要求是否正确、实际值在哪里偏离、原检查是否真的重跑过**。这也解释了为什么只复制一份通过的测试，不足以说明已经理解业务规则。

## A08｜程序结束后，数据怎样留下来？

前面处理一次运行中的值；本章让不同运行通过文件交接。**内存里的改变，不会自动成为文件里的改变。**

主线：确定路径 → 打开 → 按格式读成值 → 处理和验证 → 明确写出 → 后续运行重新读取。

### 保存前，怎样对待旧文件？

| 要做什么 | 短用法与实际效果 | 记到什么程度 |
|---|---|---|
| 读取已有内容 | `open(..., "r", encoding="utf-8")`；文件不存在时失败。 | 认熟 `r` 是读；相对路径从工作目录出发，不自动从脚本目录出发。 |
| 只建新文件，不覆盖旧文件 | 模式 `"x"`：文件已存在就拒绝。 | 需要保护已有目标时，想起这个选择。 |
| 明确替换整份内容 | 模式 `"w"`：成功打开已有文件时就清空，不等到 `write()`。 | **这项风险值得直接记住。** 后面报错不会自动恢复旧内容。 |
| 在原内容后增加 | 模式 `"a"`：追加到末尾；不存在则新建。 | 不自动补换行；是否另起一行由写入文字决定。 |

模式决定旧数据会发生什么，不是装饰参数。完整对照见「第二次保存，究竟是保护、替换，还是追加？」；示例里的路径须替换为核对过的目标。

### 从文件到数据，按什么格式解释？

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 显示了，为什么下次运行仍没有？ | 默认 `print` 写标准输出，不自动保存状态；`file.write(文字)` 明确写文件，下次可用 `read()` 读回字符串。 | 用熟 `with open(...) as file:`；离开块会关闭文件，不会撤销已写内容，已读入内存的值仍可用。 |
| 逐行读，得到什么？ | `for line in file` 每次取得字符串，可能带换行；`rstrip("\n")` 去末尾换行，`strip()` 还会移除两端其他空白。 | 清理也会改变数据，按需求选择。 |
| 标题包含逗号，能用 split 吗？ | `split(",")` 不理解 CSV 引号规则；`csv.reader` 按位置给字段列表，`csv.DictReader` 可按表头给字典。 | **有格式规则，就用对应解析工具。** `newline=""` 等完整形式查用。 |
| 读成字典，记录就合格了吗？ | 缺字段、额外列、空字符串、非法状态仍须检查；`None` 不等于 `""`。 | 解析成功不代替结构与业务检查。 |
| 筛选和排序会自动改文件吗？ | 筛选决定留谁；`sorted(rows, key=函数)` 用该函数取得比较值，返回新顺序；随后写出才改目标文件。 | `key` 接函数，不是先写 `函数()` 调用它。文字顺序不一定等于编号的数字顺序。 |
| 报告有列表与统计，不是一张平表呢？ | CSV 适合本例逐行同字段的表；JSON 可表示嵌套结构。`json.dump` 写出，`json.load` 读回 Python 值。 | 按数据关系选择，不按“哪个高级”。认熟读写方向，参数可查。 |

回看：「一行一行读，得到的是什么？」「一个人变成多个字段，逗号为什么不够了？」「知道字段名字以后，不必记它在第几列」「如果报告不是一张平表呢？」。

筛选、排序和 CSV 输出见「文件顺序不合适，怎样整理后再写出？」。有名字的取值函数与 `lambda` 短写法都可承担取比较值的工作；先看清比较依据，不为缩短代码换写法。`DictWriter` 按指定字段写 CSV，无需自己拼逗号和引号。

### 其他文件和失败，也沿同一条路线找

图片同样有“读入 → 转换 → 写出”：Pillow 解码后转换，`save` 才保存；改扩展名不等于转换格式。尺寸、灰度和安装写法查「图片也有读入、转换和写出，只是解释工具不同」，留意同名保存的覆盖风险。

**路径不存在、文字解码失败、格式解析失败、记录不合规则，是不同位置的问题。** 合法 JSON `[]` 能被解析，却不是本例要求的报告字典。回看「读写失败时，先找到哪一步还没有完成」，先找最早失败处，再修路径、格式或规则；不靠静默捕获抹掉证据。

## A09｜怎样确认运行条件没有找错？

A01 确认脚本目标；A09 再把**正在执行的文件、工作目录、解释器、依赖与配置**对齐。输出看起来不对时，先确认它属于哪次运行条件，再怀疑业务代码。

### 改了没生效、装了找不到，先比较什么？

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 这次究竟运行谁、从哪里运行、用哪个 Python？ | `Path(__file__).resolve()` 报告当前脚本位置；`Path.cwd()` 报告工作目录；`sys.executable` 报告实际解释器。 | **三份证据不必相同。** 能对照编辑器文件与实际运行；完整探针查用。 |
| 输入 python，就一定是想用的解释器吗？ | PowerShell 先解析命令名，可能遇到别名、函数或外部程序。`Get-Command` 查命令入口，运行后的 `sys.executable` 查实际解释器。 | 名字与实际运行分开核对；不凭“最新安装”或窗口标题猜。 |
| 为什么安装成功仍无法导入？ | A 的解释器安装包，不等于 B 也能找到。先核对安装和运行是否使用同一入口，再看实际导入文件位置。 | **包归属于环境，不是整台电脑共享一个安装结果。** 不同时重装所有环境。 |
| 怎样把安装、运行明确绑到同一环境？ | 让同一条 `python.exe` 路径执行 `-m pip` 和脚本；`-m` 是让这个 Python 运行指定模块。`&` 是 PowerShell 调用后面程序的写法。 | 逐渐用熟“先选解释器，再让它做事”；无需靠提示符里的环境名猜。 |
| 编辑器选了 A，终端会自动一致吗？ | 编辑器运行、调试与已有终端可能各有设置。分别运行探针，比较解释器证据。 | 界面选项可查；没红线不证明另一个终端也能导入。 |

教材探针的三行输出分别读作：`SCRIPT`＝文件，`CWD`＝工作目录，`PYTHON`＝解释器。它们是标签，不是三条需要执行的命令。脚本目录与工作目录不同，还会影响 A08 的相对文件路径。

回看：「这段输出到底属于谁？」「命令中的 python，与真正启动的解释器是一回事吗？」「包装在 A 环境，为什么 B 还是找不到？」「编辑器选了 A，终端会自动跟着变吗？」。

### 环境一致了，为什么结果仍可能不同？

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 环境变量、配置文件、默认值，谁优先？ | 优先级由代码决定。本例先选环境变量，没有才读文件，文件不存在才用默认值；已提供的非法值拒绝，不悄悄回退。 | **既看最终值，也看来源。** 不是所有应用都遵守这个顺序；编辑器设置也不自动成为程序配置。 |
| 想找代码，应该搜什么？ | 找文件名用 `Get-ChildItem`；找文件里的文字用 `Select-String`。前者定位文件，后者定位行。 | 记选择理由，筛选、递归和管道参数查用；命中不证明该行执行过。 |
| 有类型提示、格式整齐，就正确了吗？ | `values: list[int]`、`-> int` 表达类型意图，不自动执行运行时校验；formatter 整理排版，静态提示和实际测试另有作用。 | 分清各工具能证明什么，不为消除提示盲目改环境或放宽业务规则。 |
| 怎样让下次找得到同样条件？ | 留下目录、解释器、依赖安装入口、运行入口和预期观察；不只写“在某终端能跑”。 | 用项目事实写简短说明；完整版本与重建在 A12 接上。 |

回看：「配置都叫 mode，谁的值会生效？」「文件越来越多，怎样找到真正要看的位置？」「格式整齐、没有红线，是否就能证明程序对了？」「给这个小实验留下一份能照着做的说明」。

临时环境变量的保存／恢复代码和 PowerShell 版本差异可查。重点是只改实验需要的那一处、用完恢复；新进程取得父进程当时环境的副本，后来在另一终端改同名值不会自动同步，A10 将沿实际进程展开。

## A10｜程序运行后，怎样观察和停止？

A09 关注用什么条件启动谁；A10 关注启动以后。**程序文件是代码，进程是一次运行实例**：同一文件能启动多次，停止实例不等于删除文件。

第一次先找回正文里的短程序：**一行输入 → 分别观察正常结果与诊断 → 程序结束 → 核对退出码。** 这条关系清楚后，再读后面的服务观察：查到自己的实例、找到监听入口、取得回应、停止并复查。两种程序共用“运行实例”的关系，不必一开始就记整组进程和端口命令。

### 输出、诊断和退出，怎样分开读？

`normalize_line.py` 把 `"  ticket-42  "` 去掉两端空格、转成大写。它交出 `TICKET-42`，另给一条“已去掉空格”的提示，最后退出 `0`。只输入空格时，没有有效编号，诊断指出“编号为空”，退出 `2`。这是正文程序的对照结果，不是当前电脑的实况。

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 内容从哪里进、往哪里出？ | `stdin` 标准输入；`stdout` 标准输出；`stderr` 诊断通道。默认 `print` 写 stdout，诊断可另写 stderr。 | 三个短名称值得认熟；屏幕同处显示，不代表同一通道。 |
| stderr 有文字，就是失败吗？ | 诊断也可能只是提醒。程序结束后，还要按它的约定检查退出码与业务输出。 | **有诊断 ≠ 非零退出；退出 0 也不替代内容核对。** |
| 函数 return 0，就结束进程了吗？ | `return` 先把值交回调用者；本例 `sys.exit(main())` 才把结果转成进程退出码。 | 区分代码内部返回与操作系统收到的结束结果。 |
| 这次退出码从哪里取？ | 当前 PowerShell 直接运行 Python 后，及时保存 `$LASTEXITCODE`；后续其他原生程序可能替换它。 | 认得读取入口及有效时机；后台任务、独立进程的结果不能拿当前 shell 的旧值代替。 |
| 想把结果和诊断分别存下？ | `>` 把 stdout 交给文件，`2>` 把 stderr 交给文件；改变接收者，不改变程序算法。 | 认熟方向；**会覆盖已有目标**，先核对文件。完整重定向和编码差异查用。 |

回看：「一次短程序怎样交回结果」「有诊断文字，这次运行也可能成功」。本章的退出码 `2` 表示空编号；不同程序可以另作约定，不背一张通用数字含义表。

接下来改看会持续等待请求的本机文件服务。它不像短程序那样处理一行就结束，因此才需要以下查询、请求与停止证据；不是多记几条命令就能跳过对象核对。

### 查到程序、查到入口、取得回应，各证明什么？

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 某个编号的进程还在吗？ | `Get-Process -Id 4321` 查编号 4321 的进程。PID 是运行实例的编号，不是脚本名。 | 认熟 `Get-Process` 查进程、`-Id` 按编号；**数字按实际证据替换，不背示例 PID。** |
| 名字是 python，就是自己那次吗？ | 还要核对解释器位置、启动命令中的脚本／服务目录，以及启动时间。同名和同编号都不足以永久确认身份。 | 记住“存在”和“属于本次”不同；详细 `Get-CimInstance` 查询查用。 |
| 服务在预期入口等连接吗？ | `Get-NetTCPConnection` 查 TCP 连接／监听；监听行的 `LocalAddress`、`LocalPort` 是本地地址与端口，`OwningProcess` 是所属 PID。 | **端口不是 PID。** 要把入口连接到自己的实例；完整筛选参数查用。 |
| 有入口，就取得正确结果了吗？ | `Invoke-WebRequest` 发一次请求；`StatusCode` 是状态，`Content` 是正文。状态与预期内容一起看。 | 认熟请求与读结果；一次 `200` 不保证内容必然正确，更不保证以后永远可用。 |
| 该怎样停止并确认？ | 对自己前台运行的本章服务，用 `Ctrl+C` 请求结束，再查本次进程与监听。 | **停止动作不等于停止证据。** 不同程序处理中断的方式可能不同。 |

一个短写法怎样读：

```powershell
Get-Process -Id 4321
```

意思是“查询进程，按编号 4321 找”。下面只是缩减后的**示意输出**，不是当前电脑实况，也不要求运行这条示例：

```text
  Id ProcessName
  -- -----------
4321 python
```

`Id` 和 `ProcessName` 是结果的列名，不是命令。此结果只说明查询时有这个编号和名称，尚不能确认脚本身份、监听端口或服务内容。

地址 `127.0.0.1` 表示本机回环；示例端口 `8765` 是入口编号，不用背。`404` 可能是请求文件没找到，此时服务仍在运行；`200` 是 HTTP 状态，不是进程退出码。

回看：「服务为什么一直占着当前终端」「从第二个终端追到真正的回应」「发出停止动作以后，还要看一次结果」。

**停止前只认自己这次实例。** PID 会复用，不能拿旧编号去停止；先使用程序自己的结束方式。需要强制停止时，回看完整身份核对与收尾写法，不按名称结束所有 Python。查询命令报错不是“进程消失”；端口被另一程序接用，也不授权继续停止别人。

### 其余机制放在哪里，什么时候查？

| 当前问题 | 需要保留的关系 | 查用位置 |
|---|---|---|
| 管道交给下一工具什么？ | PowerShell 命令间可传带属性的对象；跨到本例 Python 标准输入时，应约定文字、路径或 JSON，不直接变成 Python 对象。JSON 文字需解析后才按字段使用。 | 「管道里流动的，什么时候是文字，什么时候是对象」。不用背整套筛选脚本。 |

| 想让提示符先回来，用什么？ | `Start-Job` 建立会话管理的后台工作，job ID 不等于 Python PID；job 显示 `Completed` 也不证明里面 Python 成功。`Receive-Job` 取回输出。 | 「如果希望提示符先回来」。等待、读取内部退出码与清理配套查，不只复制启动那行。 |

| 能启动，为什么仍拒绝访问？ | 权限针对某个身份、目标和操作。`whoami` 查身份；能启动不等于能读写任意文件。 | 「遇到权限拒绝时，先定位是哪次操作」。先找具体失败点，不直接改系统权限或全部升管理员。 |

短程序先区分**正常结果、诊断和退出码**；换成持续服务后，再补上**进程存在不等于身份正确、入口监听不等于请求内容正确、停止动作以后仍需复查**。这些关系按当前对象找回，不是一整套等待背完的 PowerShell 词表。

## A11｜怎样保存和找回一份确定的代码？

A10 观察一次运行；A11 为运行结果补上内容身份：**改的是哪份代码，准备保存哪份，怎样找回已确认的版本。**

### 怎样把修改变成明确记录？

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 编辑器保存了，为什么还没有历史？ | 保存改变 working tree（工作区）；`git add` 选取当时的内容放入 stage/index（暂存区）；`git commit` 把暂存内容记入本地历史。 | **记住三个位置与交接，逐渐用熟 add、commit。** 它们不自动替彼此完成下一步。 |
| 哪些文件变了，具体变了什么？ | `git status --short` 看状态；普通 `git diff` 比较工作区与暂存区；`git diff --staged` 比较暂存区与当前提交。 | **认熟两种 diff 看的是不同一段。** `--` 后接路径，可将比较限制到明确文件。 |
| add 后又编辑，提交保存谁？ | 普通 commit 保存暂存内容，不自动收进后来编辑的文字。程序和测试通常读工作区，所以刚测试通过不一定证明暂存内容正确。 | 沿三份内容判断提交结果，不只记“add 后接 commit”。 |
| 日志里的编号有什么用？ | `git log --oneline` 查提交历史；提交 ID 定位具体提交，`HEAD` 在本章场景指当前检出的提交。 | 认熟日志入口；编号用来记录、核对，不背。commit 保存快照，diff 比较两份内容。 |

表内省略了文件、分支等参数的写法用于识别命令，不一定能原样执行；实际操作按对应正文取得完整指令，并先核对目标。

例如：当前提交是 `Hello, learner`；改为 `Hello, team` 后 add；又改为 `Hello, everyone` 并保存。运行读到的是 `everyone`，普通 commit 准备保存的却是 `team`。

回看：「先选中内容，再把它记入历史」「add 以后继续编辑，下一次提交会得到哪一份？」。

### 不提交、放弃修改、纠正提交，各改哪里？

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 暂时不提交这个文件，但保留编辑 | `git restore --staged` 改暂存区；默认从当前提交取内容，工作区不变。 | 理解“取消待提交选择”不是删除编辑内容；完整命令带核对过的文件路径查用。 |
| 确认未提交编辑不要了 | 普通 `git restore` 默认从暂存区恢复工作区，覆盖对应文件的修改，不建立备份提交。 | **先看 status 和 diff，说清来源、目标及要放弃的内容。** 不把单文件恢复扩大成整目录操作。 |
| 改错内容已经提交了 | `git revert` 反向应用指定提交的改变并形成新提交；旧提交保留，过程中可能需要处理冲突。 | 区分未提交恢复与已提交纠正；目标提交与影响先核对，完整步骤查用。 |
| 想另开修改方向，再合回来 | branch 是指向提交的名字；`git switch` 切换，`git merge` 整合。冲突要按最终需求决定内容。 | 理解历史怎样分开、汇合；切换不等于自动保存或清空未提交修改。 |

表中的恢复写法是动作名称，不是让你直接运行的完整指令。回看「只是不想提交，和想丢掉修改，是两个动作」「如果错误已经提交，怎样保留纠正的经过？」「两个人从同一份内容继续改，历史怎样分开？」。

### 本地保存以后，怎样分享？

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 本地提交后，远端为什么没变？ | `git fetch` 取回远端信息，不自动合入当前分支；`git pull` 取回后整合；`git push` 请求远端接收提交、更新相应引用。 | **commit 不等于上传，未提交文字不会随 push 上传。** 分支和参数按项目查。 |
| 哪些内容不该跟着分享？ | `.gitignore` 主要影响尚未跟踪的匹配文件，不让已跟踪内容或历史秘密消失。 | 分享前看暂存差异及受跟踪清单；已泄露密钥须撤销或轮换，不靠改文件名解决。 |

回看：「本地提交以后，另一台机器为什么还没有变化？」「准备分享时，哪些文件不该进入这份历史？」。新实验与检查配方见「在独立目录中完成这次保存与恢复」，不需要默写整段。

主关系是**比较 → 选择内容 → 确认提交；恢复前说清从哪里取、改哪里**。A12 再验证这份确定的内容，能否在新环境重新工作。

## A12｜离开当前环境还能重新运行吗？

A11 固定源码版本；A12 先区分两种承诺：**这份输入现在能得到正确报告**，还是**别人没有旧环境也能重建结果**。前者先看输入、程序和报告；后者才加上同一份提交、依赖记录与新环境。搬过去一份旧 `.venv`，不等于证明可以重建。

### 先确认现在得到的报告，证明了什么？

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 哪份是材料，哪份是结果？ | `data/tickets.json` 是程序读取的输入，`ticket_organizer.py` 决定处理，`output/report.json` 是生成结果。 | **要试规则，改变实验副本的输入，再运行并读报告；不把改报告当改输入。** |
| 本例入口怎样传参数？ | `python .\ticket_organizer.py .\data\tickets.json .\output\report.json`：程序文件、输入、输出依次交给 Python。 | 辨认输入和输出位置；只在自己的完整实验副本中运行，输出可能替换报告。 |
| 什么结果符合这次运行预期？ | 有效 JSON 样例接受 2、拒绝 0、退出 0，报告统计也应一致；混合 CSV 接受 3、拒绝 4、退出 2。 | **内容、退出码、磁盘报告一起核对。** 数字是样例结果，不是所有输入的固定答案；非零不一概等于运行失败。 |
| 现在的报告正确，已经证明别人能重建了吗？ | 还没有。当前运行可能借用了旧环境里已经装好的依赖，文件也未必属于准备交付的提交。 | 先说清已有证据支持哪种承诺，再决定需不需要下面的干净重建。 |

回看：「先让陌生人知道，这些文件要做成什么」。第一次只在这里理解输入、输出和证据也可以；需要交付或验证重建时，再读下一部分。

### 怎样交出别人能够重新运行的程序？

| 当前问题 | 关系或短用法 | 记到什么程度 |

| 只有源码，对方还缺什么？ | Python 条件、依赖记录、输入样例、入口写法、预期输出和限制。README 说明怎样用，RELEASE_NOTES 说明版本能力与边界。 | 能解释这些条件怎样配合。本例主程序只用标准库，pytest 用于测试，不需账号。 |

|---|---|---|

本章要能说清**取了哪份内容、用什么条件重建、凭什么判断符合约定**。A13 将打开同一程序，看结果在内部怎样形成。

## A13｜把输入整理成一份可靠报告

这是 A 册的综合连接：**文件 → 原始记录 → 有效工单或拒绝原因 → 完整报告 → 命令行结果**。重点是交接，不是再背一遍前面的语法名称。

### 一张工单怎样穿过程序？

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 文件内容怎样进入程序？ | 读取原始记录（`load_rows`）：按扩展名选 CSV／JSON 解析，返回原始记录列表；CSV 的 `"1"` 与 JSON 的 `1` 此时可以类型不同。 | **解析成功不等于记录符合业务规则。** 类型提示也不执行输入检查。 |
| 谁决定这条能不能用？ | 检查一条记录并交回两种结果（`validate_row`）：检查类型、清理值、检查范围，交回 `(ticket, None)` 或 `(None, issue)`。 | 能读懂两个返回位置怎样让调用者分路，不靠有没有打印错误猜结果。 |
| 多条记录的状态谁保存？ | 整理多条记录并保存跨记录状态（`organize_rows`）：保存 `accepted`、`issues`、`seen_ids`，处理重复、排序和统计。 | 有效列表保存完整记录，集合只记已接受 ID。**只有接受过的记录占用编号。** |
| 内存报告何时成为磁盘文件？ | 把内存报告写入输出文件（`write_report`）：先写同目录临时文件，关闭后再替换目标报告。 | **旧目标保护来自顺序，不是单靠 except。** Path 细节查用；本例同一输出只安排一个写入进程。 |
| 哪层把结果交回命令行？ | 组织一次完整运行并交回命令行结果（`run`）：组织调用并返回整数；直接运行入口用 `sys.exit(run(sys.argv))` 转成退出码。 | 返回值、打印文字、报告各有接收者；测试导入模块不自动启动命令行入口。 |

这些函数名是本项目的查找入口，不是 Python 固定语法。回看「函数怎样接过上一段的结果」「文件内容先成为原始记录」「完整报告怎样才成为磁盘上的新目标」。

这里的 CSV 路线假定表头不重复、每条记录的字段数与表头一致；当前程序没有完整检查这两项。`strict=True` 只加强 CSV 语法解析，不会补出上述结构校验。接收外部 CSV 时，回 A08 的字段检查与本章「文件内容先成为原始记录」核对，不能因报告生成就宣布任何 CSV 都已经过完整验证。

### 为什么不能只靠转换和容器完成规则？

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| int 转得出来，就能接受吗？ | `"urgent"` 转换失败；`"9"` 转成整数后仍超出 1–3；`True` 虽可转成 1，本程序仍拒绝 bool。 | **原始类型、转换、业务范围是不同判断。** 普通业务拒绝不都等于异常。 |
| 空负责人怎样处理？ | owner 缺少、为 `null` 或空白文字时统一为 `unassigned`，提供其他类型仍拒绝。 | 不能把数字 `0` 或空列表当合法“未分配”。id、subject 清理后不能为空，status 仅允许 open／pending／closed。具体规则查项目。 |
| 建立集合就会自动拒绝重复吗？ | 检查 ID 是否在 `seen_ids`；重复则记录 issue 并 `continue`，不再加入有效列表。 | 容器保存事实，**判断与控制流执行规则**；先前没通过验证的记录不占 ID。 |
| 怎样排序、怎样计数？ | 先按整数 priority，再按文字 id 排序；统计只针对 accepted。 | 同优先级 ID 按文字比较，不按尾部数字。输入条数＝接受条数＋拒绝条数；一条 issue 可有多个原因。 |

回看：「一条记录怎样取得继续使用的资格」「多条记录怎样变成一份报告」。

T-201 的优先级 `1` 变成标签 `high`；T-202 的空 owner 变成 `unassigned`。两条都有效，报告接受 2、拒绝 0。混合 CSV 后四条分别因转换、空标题、重复 ID、非法状态被拒绝，仍写出报告：接受 3、拒绝 4。回看「先看 T-201 最后到了哪里」「坏记录怎样进入报告，而让下一条继续」。这些值帮助核对随书样例，不是要背的业务常识。

### 哪里失败，决定留下什么结果

| 当前问题 | 关系或短用法 | 记到什么程度 |
|---|---|---|
| 本程序的退出码怎么读？ | `0` 全部有效且报告已写；`1` 参数数量不对；`2` 报告已写但有拒绝；`3` 输入／格式约定不符；`4` 权限、编码或其他文件操作失败。 | **2 不等于报告没生成。** 编号查本程序约定，不当 Python 通用表背。 |
| 输入坏了与写出失败有何不同？ | 坏 JSON 在写出前停止；写出失败在写入阶段处理。异常类型和发生位置一起决定外部含义。 | 沿阶段找最早断点；临时文件策略不保证断电、强杀或并发写入都能恢复。 |
| 测试能证明到哪？ | 业务测试比清理后值；跨格式测试比整理后工单；受控失败测试查退出、诊断与旧目标。 | **断言查了什么，才支持什么。** 替换整个写入函数，不能单独证明真实写入函数的清理行为。 |
| 改规则后，怎样不让测试迁就代码？ | 先定新预期，加能区分新旧规则的测试，再改对应函数并重跑。 | 从差异追回交接点；Git 查清变化，A12 针对新提交重新验证重建。 |

回看：「最外层怎样告诉命令行这次发生了什么」「先用简单测试固定业务，再检查失败边界」「用一次小改动检查自己能否找回关系」。`tmp_path`、`capsys`、`monkeypatch` 分别帮助隔离临时文件、收集输出、受控替换；完整测试写法在对应例子查，不默写整套。

运行前按「在自己的实验目录里运行一次」复制完整项目，不在随书参考副本内产生状态。输入和输出用分开的普通文件，核对输出将替换谁，不把任意旧文件当可丢弃报告。

本章把整册接成：**解析器解释格式，验证函数判断一条，整理函数保存跨记录状态，写出函数改变磁盘，入口向外说明结果**。当前程序仍是本地离线工具；B 册才加入 HTTP 协作，不要把模块导入画成网络请求。
